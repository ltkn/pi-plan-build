The evidence rule the spec was written to: A claim is load-bearing when the build would act differently if it were false: a number or bound, what this repository, its build, runtime or configuration does, or how an external service behaves. Each one carries its evidence beside it: a path:line that says it, a probe (probe: <what you ran>; conclusion: <what it showed>), or, for a value this change defines (a new status, error, event or stored value), the Acceptance line that pins it, whose red test is the proof. A claim about existing code or a service needs the path:line or the probe: a test written from the same belief passes even when the belief is wrong. What nothing settles yet is tagged `assumed: <what would falsify it>` right after it. Anything else needs no evidence.

A claim is settled when it carries that evidence or the tag. Check a cited path:line resolves to what the claim says before believing it, and that a value an Acceptance line is said to pin is one this change defines.

Report every load-bearing claim that is neither settled nor tagged: P1 when getting it wrong would change the design, the data model or a contract; P2 otherwise.
